# PRD — 왈왕 (반려견 동반 장소 지도)

> 작성일 2026-08-10 · @나영 한
> 4주 공모전 MVP 기준. 심사 데모에서 **하나의 흐름이 끊김 없이 도는 것**을 최우선으로 한다.
> `[논의 필요]` 표시가 붙은 항목은 아직 확정되지 않았다. (이 문서는 결정 사항을 반영해 갱신됨)

---

## 1. 문제 정의

반려견 보호자는 외출 전 "여기 우리 개 데리고 들어갈 수 있나"를 확인할 방법이 없다. 현재는 포털 리뷰를 뒤지거나, 전화하거나, 그냥 가서 거절당한다.

특히 **견종 크기에 따라 결과가 갈린다**는 점이 핵심이다. "반려견 동반 가능"이라고 적혀 있어도 대형견은 거절되는 경우가 많아, 단순 가능/불가 정보로는 부족하다.

## 2. 타겟 사용자

- **주 사용자** — 대형견 보호자. 거절 경험이 잦고 사전 확인 필요성이 크다.
- **사용 맥락** — 외출 직전/중 모바일. 데스크톱 시나리오는 고려하지 않는다.

## 3. 목표와 성공 기준

### 제품 목표

크기 조건까지 포함된 반려견 동반 정보를, 사용자 리뷰로 축적하고 신뢰도와 함께 제공한다.

### 크기 구분 정책 (확정)

크기 축은 **소·중형 / 대형 두 가지**로 통일한다. 상태 표기, 리뷰 입력, 추천 키워드 모두 동일한 2단계를 쓴다. 선택지를 줄이면 리뷰 입력이 빨라지고 각 구간 신뢰도가 두 배 빨리 확정된다.

### 공모전 성공 기준

| 항목        | 기준                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 데모 완주   | 지도 확인 → 방문 → 리뷰 작성 → 지도 반영 → 도장 획득까지 끊김 없이 시연 |
| 데이터 밀도 | 시연 지역 내 가게 40~60곳, 목 리뷰 200개 내외                           |
| 차별점 전달 | 크기 구분과 신뢰도 개념이 화면만 보고 이해되는 것                       |

### 명시적 비목표

전국 커버리지 · 실사용자 리텐션 · 수익 모델 · 웹 버전.

## 4. 범위

**In Scope** — 지역 1곳(서울숲/한강공원 인근급) · 업종 3종(공원·산책로, 카페, 식당) · Android 앱(iOS는 빌드 환경 확보 시에만).

**Out of Scope** — 예약/결제/메시징 · 커뮤니티 · 푸시 알림 · 관리자 웹(DB 직접 수정으로 대체).

## 5. 기능 요구사항

우선순위: **P0**(없으면 성립 안 됨) / **P1**(심사 임팩트 큼) / **P2**(일정 밀리면 컷).

### F-00. 정보 구조 (P0)

하단 탭은 **지도 / 저장 / 마이** 3개, 지도가 첫 항목이자 로그인 직후 기본 화면.

- 상단: 장소 검색창(단순 텍스트 검색) + [추천받기] 진입
- 중앙: 지도 + 핀
- **추천받기는 탭이 아니라 지도 화면 상단에 배치.**
- **리뷰 작성은 탭이 아니라 가게 상세의 [리뷰 쓰기]로만 진입.** (가게 선택을 먼저 강제)

### F-01. 지도 + 검색 + 가게 상세 (P0)

관공서 API로 시드한 가게를 지도에 핀으로 표시.

**상태 3단계**: `가능`(동반 확인) / `불가`(거절 확정) / `미확인`(리뷰 부족·신뢰도 미달).

**크기 상태 표기 (확정)** — 크기 조건은 **핀 색이 아니라 상세 시트의 텍스트로** 전달. 핀은 크기와 무관하게 동일 규칙으로 그린다.

```
소·중형견   가능      (?)
대형견      미확인    (?)
```

(?) 탭 시 근거를 건수로 설명한다 — "소·중형견 확인 리뷰 3건 / 대형견 확인 리뷰 0건, 리뷰가 더 모이면 상태가 확정돼요". **내부 가중치 수치는 노출하지 않는다.**

**요구사항**

- 검색창: 가게명 부분 일치. 결과 선택 시 지도 이동 + 상세 시트.
- [추천받기] 진입 요소(F-07).
- 핀 탭 → 하단 시트 상세: 가게명, 업종, 크기별 상태 2줄 + 각 (?), 리뷰 건수, 최근 인증 시점, [리뷰 쓰기], [저장].
- 크기 선택 UI 기본값 **미선택** (오등록 방지).

**제약**

- 검색은 가게명 텍스트만. 업종·조건 검색은 F-07 역할.
- **핀은 이미지 애셋으로 렌더링.** 커스텀 컴포넌트 마커는 성능상 미사용.

### F-02. 회원 (P0)

이메일 + 닉네임 + 비밀번호 자체 회원가입.

- 이메일/닉네임 중복 검사, 로그인 후 토큰 안전 보관(재실행 시 자동 로그인), 닉네임은 리뷰·여권에 사용.
- 소셜 로그인·이메일 인증·비밀번호 재설정은 범위 외. 비밀번호는 서버 해싱 저장(평문 금지).

### F-03. 리뷰 작성 플로우 (P0)

```
가게 상세 → [리뷰 쓰기]
→ 결과 선택 (들어갔어요 / 거절당했어요)
   ├─ 들어갔어요 ─→ 영수증 OCR(관문) → 반려견 사진(인앱 카메라, 필수)
   │                → 크기 → 해시태그 → 자유 텍스트 → 등록 → 도장 획득
   └─ 거절당했어요 ─→ (영수증·사진 없음) → 크기 → 해시태그 → 자유 텍스트 → 등록 (도장 없음)
```

**결과 선택을 맨 앞에 두는 이유** — 거절 시 영수증이 없고 사진 찍을 여유도 없다. 먼저 경로를 나눠 거절 경로는 입력 한 화면으로 끝낸다.

**요구사항**

- 진입점은 [리뷰 쓰기] 하나뿐.
- 결과 입력은 1문항 2택, **상세 시트 위 작은 모달**(전체 화면 아님). 선택 결과는 이후 화면 상단에 계속 표시·수정 가능. 거절→들어갔어요로 바꾸면 영수증·사진 단계로 되돌림.
- 크기 입력 1문항 2택(소·중형 / 대형), 기본값 미선택.
- 해시태그는 사전 정의 목록 선택, 자유 텍스트는 선택 입력.
- 결과가 `거절`이면 **등록 버튼 바로 위**에 경고 문구 — "허위 리뷰는 가게에 피해가 될 수 있어요 ㅜㅜ". (상단에 두면 스크롤로 사라짐)
- 등록 즉시 지도에 반영.

**해시태그 목록 (확정)**

```
#넓은마당 #펜스완비 #잔디밭 #뛰놀기좋아요 #반려견전용공간 #테라스넓음
#주차편해요 #급수대있음 #배변봉투제공 #강아지방석 #반려견메뉴 #강아지식기제공
#조용해요 #한적해요 #소심견도편해요 #친구들많아요 #첫나들이추천 #오래머물기좋아요 #목줄필요해요
```

거절 전용 해시태그는 **두지 않는다(확정)**. 거절 사유는 자유 텍스트로 받는다.

**경로별 단계 비교**

| 단계                            | 들어갔어요          | 거절당했어요                                  |
| ------------------------------- | ------------------- | --------------------------------------------- |
| 결과 선택 (S-18)                | 필수                | 필수                                          |
| 영수증 OCR (S-06)               | 필수, 차단 관문     | 건너뜀                                        |
| 반려견 사진 (S-07)              | 필수, 인앱 카메라만 | 건너뜀                                        |
| 크기·해시태그·자유텍스트 (S-08) | 필수                | 필수                                          |
| 도장 (S-09)                     | 지급                | **미지급(확정)** — 사진 없어 실루엣 생성 불가 |

**제약** — 반려견 사진 갤러리 업로드 제외(현장 촬영만). GPS 자동 가게 판별은 MVP 제외. 자유 텍스트는 받되 경로 추천 데이터로는 미활용.

### F-04. 영수증 OCR 인증 (P0)

영수증 이미지에서 **상호명만** 추출해 선택 가게와 일치 판단. `들어갔어요` 경로에만 적용.

| 조건               | 처리                                                            |
| ------------------ | --------------------------------------------------------------- |
| 유사도 임계값 이상 | 인증 완료 배지 → 진행                                           |
| 유사도 미만        | "이 가게가 아닌 것 같아요" → [다시 촬영]/[가게 다시 선택], 차단 |
| OCR 판독 실패      | "영수증을 읽지 못했어요" → [다시 촬영], 차단                    |

**매칭 규칙** — 부분 일치 + 공백·특수문자 제거 + 지점명("서울숲점") 제거 후 비교. 날짜 추출·가중치 3단계는 폐기. OCR은 **통과/차단** 두 결과만.

**확정** — 들어갔어요 경로는 영수증 필수. 영수증 없이 성공 리뷰 남기는 경로 없음.
**[논의 필요]** — 유사도 임계값 수치는 실제 영수증 샘플로 매칭률 측정 후 결정.

### F-05. 신뢰도 집계 (P0)

리뷰를 집계해 크기별 상태를 확정. 크기 2구간 각각 `가능`/`불가`/`미확인` 산출. 상세 화면에는 인증 리뷰 건수와 최근 인증 시점만 노출.

**확정 기준 (건수 AND 비율, 비대칭)**

| 상태   | 기준                                       |
| ------ | ------------------------------------------ |
| 불가   | 거절 ≥ **3건** AND 거절 비율 ≥ **55%**     |
| 가능   | 동반확인 ≥ **4건** AND 동반 비율 ≥ **70%** |
| 미확인 | 그 외 전부                                 |

- **분모 N = 동반가능/거절 태그가 달린 리뷰만** 집계(일반 맛 리뷰 제외).
- **비대칭 근거** — "가능" 오탐은 헛걸음 → 앱 신뢰 붕괴이므로 더 까다롭게, "불가" 오탐은 기회 손실이라 조금 더 쉽게.
- 이 값으로 두고 **목 리뷰로 테스트하며 조정**한다.
- **시간 가중치**(최신 정보 반영)는 AI 테스트 후 추후 확정. `[논의 필요]`

### F-06. 거절 리뷰 + 대안 추천 (P1)

거절 리뷰 수집 자체는 F-03에 포함되어 확정(영수증·사진 없음, 도장 미지급).

**대안 추천 (S-09 거절 완료 화면 내)** — 거절 직후 인근 `가능` 가게를 보여준다.

- **단일 가게 정보 카드 최대 3개** 나열(코스 아님). 카드: 가게명, 업종, 현재 위치로부터 거리, 크기별 상태.
- 선정 기준: 현재 가게 반경 내, 동일 업종, 해당 크기 `가능`. 거리순.
- 카드 탭 → 가게 상세 시트.

**구현 방향 (확정)** — PostGIS 반경 + 크기상태 조인으로 가능. **우선 최대 3개**, 완화 조건으로 반경을 넓혀 최대 3개까지 확보 시도. **후보 0~3개를 전제로 화면 구성**(부족/0개 폴백 포함). 벡터 검색은 붙이지 않고 SQL 필터로.

### F-07. 코스 추천 (P0/P1)

지도 상단 [추천받기] 진입.

**MVP (P0)** — 사전 정의 키워드 선택.

| 키워드 | 옵션                           |
| ------ | ------------------------------ |
| 크기   | 소·중형 / 대형                 |
| 목적   | 산책 / 식사 / 카페 (복수 선택) |
| 시간   | 1시간 / 반나절 / 하루          |

시간 → 지점 수 매핑: 1시간=2, 반나절=3–4, 하루=4. SQL 하드필터 + 거리로 3–4지점 선정 → **티맵 보행자 경로 API**로 도보 경로 받아 지도에 선 표시. 결과 화면에서 코스 저장 가능.

**확장 (P1)** — 벡터 검색 vibe 정렬, 자연어→LLM 파싱, 후보 제시→선택→경로 재생성.

**제약** — 티맵 경유지 상한 5개(4지점 초과는 분할 호출). 좌표 변환·가공은 백엔드에서 `{latitude, longitude}` 배열로 내려줌.

### F-08. 저장 (P1)

가게·코스를 저장 탭에서 다시 본다.

- 진입점: 가게 상세 [저장], 코스 결과 [코스 저장].
- 저장 탭 상단 세그먼트로 장소/코스 구분. 장소 선택→지도 이동+상세, 코스 선택→코스 결과 재현. 빈 상태 안내 + 지도 버튼. 저장 해제 가능.
- **저장 코스 열기 (확정)** — 재계산하지 않고 **코스 id를 재사용**한다.

### F-09. 마이 + 실루엣 도장 + 여권 (P2)

마이 = 상단 요약 숫자 + 하단 여권.

- **마이(S-16)** — 닉네임, **내가 쓴 리뷰 수 / 모은 도장 수 두 숫자만**. 리뷰 수 탭 → 내 리뷰 목록(S-17). 도장 수는 탭 없음(아래 여권이 그 내용). 하단에 **여권 바로 노출**. 로그아웃. 프로필 편집·설정·이력 없음.
- **내 리뷰 목록(S-17)** — 최신순(가게명·업종·작성일·크기·결과). **썸네일 없음.** 항목 탭 → 지도+상세.
- **여권(S-13)** — 리뷰 사진에서 반려견 실루엣 추출해 도장 생성. 페이지당 5~10개, **사전 정의 슬롯 좌표 내 랜덤**(크기·각도 변형, 겹침 방지). 초과 시 좌우 스와이프.
- **도장 상세 모달(S-14)** — 방문 날짜, 가게명(탭→상세), 당시 반려견 원본 사진(가능 시), [이미지로 저장](가능 시, 화면 캡처 우선).
- **폴백** — 세그멘테이션 품질 미달 시 기본 발도장 이미지로 전환(구조·모달 유지). 판단 기한 3주차 초.

| 항목           | 기준                                                    |
| -------------- | ------------------------------------------------------- |
| 지도 성능      | 핀 60개에서 팬·줌·상세 열기 체감 지연 없음              |

## 8. 데이터 모델 개요

상세 스키마는 백엔드 소관. 프론트 의존 최소 형태만 기술.

- **Place** — id, 이름, 업종, 좌표, 크기별 상태(소·중형/대형 각각 가능·불가·미확인), 리뷰 건수, 최근 인증 시점
- **Review** — id, place_id, user_id, 크기(소중형/대형), 결과(성공/거절), OCR 매칭 결과, 사진 URL, 해시태그, 자유 텍스트, 생성일시
- **User** — id, 이메일, 닉네임, 도장 목록
- **Course** — 장소 배열, 경로 좌표 배열, 총 거리, 총 소요시간
- **Saved** — user_id, 타입(place/course), 대상 id, 저장일시

> 프론트 타입은 [`src/types/`](../src/types/)에 정의. 목 데이터는 [`src/mocks/`](../src/mocks/).

## 9. 리스크

- **R-01 OCR 차단 관문화(상)** — 매칭 실패가 곧 플로우 중단. 임계값 관대 + 전처리 충분히. 데모 영수증 사전 검증.
- **R-02 세그멘테이션 품질(중)** — 2주차 사진 20장 선검증, 미달 시 3주차 초 발도장 전환.
- **R-03 RN 첫 빌드·네이티브 모듈(중)** — 1주차 첫날 dev build 실기기 검증(완료). 카메라 모듈 2주차 즉시 실기기 확인.
- **R-04 데모 환경(하)** — 시드 기반 오프라인 시연 영상 백업.
