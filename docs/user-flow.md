# 유저 플로우 — 왈왕

> 작성일 2026-08-10 · @나영 한
> [PRD](./prd.md)의 화면 목록(S-01 ~ S-18)을 기준으로 한다. 각 플로우는 진입점, 정상 경로, 이탈·실패 분기를 함께 기술한다. (결정 사항 반영해 갱신됨)

---

## 전체 구조

```
[스플래시 S-01]
   ├─ 토큰 있음 ──────────────→ [지도 홈 S-04]
   └─ 토큰 없음 → [로그인 S-02] ─→ [지도 홈 S-04]
                      └→ [회원가입 S-03] ─→ [지도 홈 S-04]

[지도 홈 S-04]  ← 로그인 후 기본 진입 화면, 가운데 탭
   · 상단 : 장소 검색창(단순 텍스트) + 크기 필터
   · 중앙 : 지도 + 핀 (위치정보 미사용·고정 기본 좌표)
   · 우하단: [추천받기] FAB
   · 하단 탭 : 저장 / 지도 / 마이 (지도 가운데·기본 진입)
   ├─→ 핀 탭 → [상세 시트 S-05] → [리뷰 쓰기] → 플로우 A
   ├─→ 우하단 FAB [추천받기] → [키워드 S-10] → 플로우 B
   ├─→ 저장 탭 → [저장 S-15] → 플로우 C
   └─→ 마이 탭 → [마이 S-16] → 플로우 D
```

하단 탭은 **저장 / 지도 / 마이** 3개, 지도가 가운데 탭이자 로그인 직후 기본 진입 화면. 추천받기는 탭에서 빼고 **지도 우하단 FAB로 배치**. 리뷰는 별도 탭이 아니라 가게 상세에서만 진입. 지도는 **위치정보(GPS) 미사용** — 내 위치 기반 표시 없이 고정 기본 좌표로 초기화.

## 플로우 0 — 온보딩

### 0-1. 첫 실행

```
앱 실행 → [S-01 스플래시] 저장 토큰 확인 → 없음 → [S-02 로그인]
  · 이메일, 비밀번호 입력 / "회원가입" 링크
```

### 0-2. 회원가입

```
[S-02] → "회원가입" → [S-03]
  · 이메일 → 형식 검증 → 중복 검사
  · 닉네임 → 중복 검사
  · 비밀번호 → 8자 이상 검증
  → 가입 완료 → 자동 로그인 → [S-04 지도 홈]
```

**실패 분기**

| 상황               | 처리                               |
| ------------------ | ---------------------------------- |
| 이메일/닉네임 중복 | 필드 하단 인라인 에러, 제출 비활성 |
| 비밀번호 조건 미달 | 입력 중 실시간 안내                |
| 네트워크 오류      | 토스트, 입력값 유지                |

> 이메일 인증 메일 없음 → 가입 즉시 로그인. 온보딩 튜토리얼 없음(지도 자체가 설명 없이 이해되는 게 목표).

## 플로우 A — 리뷰 쓰기 (핵심)

데모의 중심. 진입점은 **가게 상세의 [리뷰 쓰기] 하나뿐**. **결과 선택이 맨 앞**에 온다.

```
[S-05] → [리뷰 쓰기] → [S-18 결과 선택]
   ├─ 들어갔어요 ──→ [S-06 영수증 OCR] → [S-07 사진] → [S-08 입력] → [S-09 완료+도장]
   └─ 거절당했어요 ─→ (영수증·사진 없음) ─────────→ [S-08 입력] → [S-09 완료, 도장 없음]
```

크기 축은 **소·중형 / 대형** 두 가지로 통일.

### A-0. 지도에서 가게 찾기

```
[S-04 지도 홈]
  · 검색창 — 가게명 텍스트 검색 / 크기 필터
  · 우하단 FAB [추천받기] (플로우 B)
  · 지도 — 위치정보 미사용, 고정 기본 좌표(서울숲)로 초기화
  · 핀 — 크기와 무관하게 동일 규칙 표시(크기별 색 갱신 없음)
  → 핀 탭 또는 검색 결과 탭 → [S-05 상세 시트]
      · 가게명, 업종
      · 크기별 상태 2줄:  소·중형견 가능 (?) / 대형견 미확인 (?)
      · 리뷰 건수, 최근 인증 시점
      · [리뷰 쓰기] / [저장]
```

**검색창** — 서버 가게명 부분 일치 조회, 항목 선택 시 지도 이동+상세. 업종·크기 검색은 범위 외(추천받기가 담당).

**크기 상태 표기** — 핀 색이 아니라 상세 시트 텍스트. (?) 탭 시 건수로 설명:

```
┌────────────────────────────┐
│ 대형견 · 미확인             │
│ 소·중형견 확인 리뷰  3건    │
│ 대형견 확인 리뷰     0건    │
│ 리뷰가 더 모이면 확정돼요   │
└────────────────────────────┘
```

내부 가중치 수치는 숨기고 건수만. **크기 선택 기본값은 미선택**(오등록 방지). 상세는 전체 화면이 아니라 하단 시트(지도 맥락 유지, 전환 애니메이션 없음).

### A-1. 결과 선택

```
[S-05] → [리뷰 쓰기] → [S-18 결과 선택]
  · "들어갈 수 있었나요?"  [들어갔어요] / [거절당했어요] — 필수 택1
```

| 선택         | 다음                             |
| ------------ | -------------------------------- |
| 들어갔어요   | A-2 영수증 → A-3 사진 → A-4 입력 |
| 거절당했어요 | A-2·A-3 건너뛰고 A-4 입력        |

**화면 형태 (확정)** — 전체 화면이 아니라 **상세 시트 위 작은 모달**. S-18은 이 모달을 가리킨다. 결과 값은 이후 화면 상단에 계속 표시(되돌리기 대비).

### A-2. 영수증 OCR — 가게 확인 관문 (들어갔어요만)

```
[S-18] → 들어갔어요 → [S-06 영수증 촬영]
  · [촬영] 또는 [갤러리에서 선택]
  → 업로드 → OCR(상호명만) → 선택 가게명과 유사도 비교
```

| 판정               | 처리                                                         | 다음     |
| ------------------ | ------------------------------------------------------------ | -------- |
| 유사도 임계값 이상 | 인증 완료 배지                                               | A-3 진행 |
| 유사도 미만        | "이 가게가 아닌 것 같아요 ㅜ" — [다시 촬영]/[가게 다시 선택] | 차단     |
| OCR 판독 실패      | "영수증을 읽지 못했어요. 다시 첨부해주세요" — [다시 촬영]    | 차단     |

OCR은 상호명 일치 판단만(날짜·가중치 없음). 유사도 미달은 가게 재선택 경로도, 판독 실패는 재촬영만.

**확정** — 들어갔어요 경로는 영수증 필수. **거절 경로엔 검증 수단이 없다**(아래 참고).

**거절 리뷰 검증 공백 대응**

- **대응 1 (확정)** — 리뷰 작성 화면 경고 문구(A-4). 상습 악플은 신고 시 불이익.
- **대응 2 (확정)** — 신뢰도 확정 기준을 건수 AND 비율로 사전 정의(PRD F-05): 불가 = 거절 ≥3건 AND 거절비율 ≥55%, 가능 = 동반확인 ≥4건 AND 동반비율 ≥70%. 분모는 동반태그 리뷰만.
- GPS 반경 확인은 실내 정확도 문제로 보류.

**[논의 필요]** — 유사도 임계값 수치는 영수증 샘플로 매칭률 측정 후. 지점명·공백·특수문자 제거 전처리는 유지.

### A-3. 반려견 사진 (들어갔어요만)

```
[S-07] · 인앱 카메라 촬영만 — 필수 · 갤러리 없음
  → 촬영 → 미리보기 → [다음]/[다시 찍기]
```

현장 촬영만 받아 현장성 담보. 거절 경로는 이 단계 건너뜀 → **거절 리뷰엔 도장 미지급**(도장이 이 사진 실루엣에서 나오므로). 데모 한정 갤러리 허용은 지금 고려 X.

### A-4. 리뷰 내용 입력 (두 경로 합류)

```
[S-08]
  · 상단: A-1 결과 표시(수정 가능)
  · 크기 선택 (소·중형 / 대형) — 필수, 기본값 미선택
  · 해시태그 — 선택, 사전 정의 목록
  · 자유 텍스트 — 선택
  · [거절인 경우] 등록 버튼 바로 위 경고:
      "허위 리뷰는 가게에 피해가 될 수 있어요 ㅜㅜ"
  → [등록]
```

**해시태그 목록 (확정)**

```
#넓은마당 #펜스완비 #잔디밭 #뛰놀기좋아요 #반려견전용공간 #테라스넓음
#주차편해요 #급수대있음 #배변봉투제공 #강아지방석 #반려견메뉴 #강아지식기제공
#조용해요 #한적해요 #소심견도편해요 #친구들많아요 #첫나들이추천 #오래머물기좋아요 #목줄필요해요
```

거절 전용 해시태그는 두지 않음(확정). 자유 텍스트는 저장하되 경로 추천엔 미활용.

**경고 문구** — 결과가 거절일 때만, **등록 버튼 바로 위**. 결과를 거절→들어갔어요로 바꾸면 A-2로 되돌려 영수증·사진 단계를 받는다.

### A-5. 완료

```
[등록] → 서버 저장·신뢰도 재집계 → [S-09] → [S-04 지도 홈] (핀 상태 갱신됨)
```

**들어갔어요** — 도장 획득 연출 + "지도에 반영되었어요" + [지도로 돌아가기]/[공유하기].

**거절당했어요**

```
[S-09] · 도장 없음
  · "알려주셔서 고마워요, 지도에 반영되었어요"
  · "대안 추천 받으시겠어요?"
  · [인근에 이런 곳은 어때요]
      가게 카드 최대 3개 — 가게명·업종·거리(방금 가게 기준)·크기별 상태(해당 크기 `가능`)
      → 카드 탭 → [S-05 상세 시트]
  · [지도로 돌아가기]
```

거절 리뷰는 **도장 미지급(확정)**, 대안 추천이 유일한 보상. **카드는 최대 3개**(코스 아님). 선정: 반경 내·동일 업종·해당 크기 `가능`, 거리순.

**구현 (확정 방향)** — PostGIS 반경+상태 조인. 우선 최대 3개, 완화 조건으로 반경 확대. **후보 0~3개 전제로 화면 구성**(0개 폴백 포함). 벡터 검색 없이 SQL 필터.

## 플로우 B — 추천받기

```
[S-04] 우하단 FAB [추천받기] → [S-10 키워드 선택]
  · 크기 — 소·중형 / 대형
  · 목적 — 산책 / 식사 / 카페 (복수 선택)
  · 시간 — 1시간 / 반나절 / 하루
  · 시작 지점 — 위치정보 미사용, 사용자가 수동 지정(지도 중심/검색 선택)
  → [코스 만들기]
  → 서버: SQL 하드필터 → 거리 정렬 → 3~4지점 → 티맵 보행자 경로 → 좌표 배열
  → [S-11 코스 결과]
      · 지도 폴리라인 + 순번 핀
      · 하단 시트 지점 목록(이름·업종·예상 소요)
      · 총 거리, 총 소요시간
      · [코스 저장]
      → 지점 탭 → [S-05 상세 시트]
```

**시간 → 지점 수**: 1시간=2, 반나절=3~4, 하루=4. 티맵 경유지 상한 5개 → 최대 4지점.

**실패 분기**

| 상황                | 처리                                                      |
| ------------------- | --------------------------------------------------------- |
| 조건 맞는 장소 부족 | 조건 완화 결과 + "조건을 조금 넓혔어요"                   |
| 경로 API 실패       | 폴리라인 없이 순번 핀+직선 연결 폴백, 총 거리는 직선 기준 |

경로 API 의존 구간이라 폴백 필수(데모 리스크).

## 플로우 C — 저장

```
[저장 탭] → [S-15]
  · 상단 세그먼트: 장소 / 코스
  · 장소 — 저장 가게 목록(이름·업종·크기별 상태) → 탭 → 지도+[S-05]
  · 코스 — 저장 코스 목록(지점 수·총 거리·총 소요) → 탭 → [S-11] 재현
  · 스와이프/롱프레스 → 저장 해제
```

저장은 [S-05]와 [S-11]에서만. 빈 목록 시 안내 + 지도 버튼.

**저장 코스 열기 (확정)** — 경로 재계산하지 않고 **코스 id 재사용**.

## 플로우 D — 마이 (P2)

### D-1. 마이 화면

```
[마이 탭] → [S-16]
  ┌ 상단: 닉네임 / 내가 쓴 리뷰 수 | 모은 도장 수 (두 숫자만)
  │         리뷰 수 탭 → [S-17]
  ├ 하단: "나의 여권" — 별도 진입 없이 바로 노출
  │         도장 탭 → [S-14]
  └ 로그아웃
```

상단은 숫자 두 개만(프로필 편집·설정·이력 없음). 도장 수는 탭 없음(아래 여권이 그 내용), 리뷰 수만 탭 가능.

### D-2. 내가 쓴 리뷰 목록

```
[S-17] · 최신순(가게명·업종·작성일·크기·결과) · 썸네일 없음
  · 빈 상태 — "아직 남긴 리뷰가 없어요" + 지도로 가기
  → 항목 탭 → 지도+[S-05]
```

썸네일 제외(거절 리뷰엔 사진 없어 줄이 들쭉날쭉). 사진은 여권 도장 모달에서.

### D-3. 여권 (마이 하단 임베드)

```
[S-13] · 여권 배경 위 도장 배치 · 페이지당 5~10개
  · 사전 정의 슬롯 좌표 내 랜덤(크기·각도 변형) · 초과 시 좌우 스와이프
```

완전 랜덤이 아니라 슬롯 내 랜덤(겹침·이탈 방지).

### D-4. 도장 상세 모달

```
[도장 탭] → [S-14]
  · 방문 날짜 · 가게명(탭→[S-05]) · 당시 반려견 원본 사진(가능 시) · [이미지로 저장](가능 시) · 닫기
```

| 항목        | 조건                          | 폴백          |
| ----------- | ----------------------------- | ------------- |
| 원본 사진   | 리뷰에 원본 URL 보관          | 실루엣만 크게 |
| 이미지 저장 | 화면 캡처 또는 서버 카드+권한 | 버튼 미노출   |

이미지 저장은 모달 영역 캡처가 가장 싸다. 세그멘테이션 미달 시 발도장 폴백(구조·내용 유지).

## 데모 시나리오

심사에서 이 하나의 흐름만 끊김 없이 돌면 된다.

```
1. 지도 진입 — 핀·검색창 확인
2. 검색창에 가게명 → 결과 탭 → 카페 상세에서 '대형견 미확인' 확인, (?)로 건수 확인
3. [리뷰 쓰기] → [들어갔어요]
4. 영수증 촬영 → 상호명 매칭 통과, 인증 배지
5. 인앱 카메라로 반려견 사진 → 크기 대형 → 해시태그 → 등록
6. 도장 획득 연출
7. 지도 복귀 → 같은 가게 상세 재확인 — 대형견 미확인→가능 전환 확인
8. 지도 우하단 [추천받기] → 대형+산책+반나절 → 경로 그려진 결과 → [코스 저장]
9. 저장 탭에서 방금 저장한 코스 확인
```

**사전 준비**

- 4단계 영수증은 미리 촬영해 **상호명 매칭 통과 확인**(OCR이 차단 관문이라 데모 성패를 가름).
- 2단계 가게는 리뷰 1건만 더 들어오면 확정되도록 시드 조정.
- 5단계 인앱 카메라 권한 미리 허용.
- 8단계 코스 사전 1회 호출해 정상 반환 확인.
- 네트워크 장애 대비 시연 영상 백업.
